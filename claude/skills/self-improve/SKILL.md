# 자기 개선

## 진단

1. 원 사건과 관련 문서·코드의 실제 상태를 대조한다.
2. 결과가 잘못된 마지막 시점이 아니라 최초로 근거 없는 결정을 확정한 시점을 찾는다.
3. 원인이 발견·결정 정당성·생산 게이트·검증 중 어느 실패인지 분류하고 이를 허용한 발동·정보·판정 기준·도구를 추적한다.
4. 규칙이 목적을 해쳤다면 그 범위·방향·소속을 추적한다.
5. `~/.claude/harness-authoring.md`와 `~/.claude/rules/harness-authoring.md`, 대상 유형의 rule을 읽는다. 개선 대상이 자기수정 구조면 `~/.claude/self-harness-architecture.md`도 읽는다.

## 개입

다음 실행에도 남으며 실패 원인을 직접 바꾸는 가장 작은 개입을 고른다. 소속은 `~/.claude/rules/harness-authoring.md`에서 정한다. skill의 미발동은 description부터 검사하고, 겹친 책임은 분리하며, 기존 책임으로 원인을 바꿀 수 없을 때만 구성물을 추가한다.

## 변경과 검증

1. 원인과 최소 수정안을 사용자에게 제안하고 승인받는다.
2. 승인된 Claude Code 또는 shared 문서를 편집한다.
3. 사건마다 새 `meta-doc-critic`에 대상 경로·원 사건·직접 연결된 workflow만 전달하고 작성자의 결론이나 기대 답은 제외한다. agent를 쓸 수 없으면 분리된 읽기 전용 검수를 한 번 수행하고 한계를 밝힌다.
4. critic 지적은 작성자가 반영 여부와 직접 회귀를 대조하고 종료한다. 계약이 다시 바뀌거나 직접 판정하기 어려울 때만 이유와 범위를 제시해 승인받고 별도의 fresh critic을 사용한다.
5. 원인이 Codex에도 존재할 구조적 근거가 있을 때만 `port-harness-change`를 사용한다. 모델 성향이나 Claude Code 기능에 묶인 문제는 Claude Code에 남긴다.
