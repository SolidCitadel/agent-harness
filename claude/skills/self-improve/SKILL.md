# 자기 개선

## 진단

1. 원 사건과 관련 문서·코드의 실제 상태를 대조한다.
2. 확인된 문제를 실행 실패·부주의로 종결하지 않는다. 규칙을 적용하지 못했다면 그 실패를 허용한 발동·정보·판정 기준·생산 프레이밍·검증·게이트·도구를 추적한다.
3. 규칙을 적용한 결과가 목적을 해쳤다면 규칙 자체의 범위·방향·소속을 추적한다.
4. `~/.claude/rules/meta-doc.md`와 대상 유형의 type-rule을 읽는다. 개선 대상이 자기수정 기계면 `~/.claude/self-harness-engineering.md`도 읽는다.

## 개입 선택

확인된 문제마다 다음 실행에도 남는 최소 개입을 고른다.

삭제·병합·발동·정보·순서·생산 프레이밍·규칙의 범위와 방향·판정 기준·검증·게이트·도구를 전체 실패 경로에 대조해 원인을 직접 바꾸는 가장 작은 개입을 고른다. 기존 규율을 되풀이하지 않고, 규율이 실행되지 않았다면 그 경로를 바꾸며 규율이 목적을 해쳤다면 규율 자체를 바꾼다.

## 변경

1. 사용자에게 원인과 최소 수정안을 제안하고 승인받는다.
2. 승인된 문서를 편집한다.
3. Meta-doc critic에는 대상 경로·원 사건·직접 연결된 workflow만 전달해 전체를 검수시킨다.
4. 지적을 반영한 최종 상태를 다시 검수하고 완결 마킹한다.
5. 원인이 Codex에도 존재할 구조적 근거가 있을 때만 `port-harness-change`를 사용한다. 모델 성향이나 Claude 기능에 묶인 문제는 Claude에 남긴다.
