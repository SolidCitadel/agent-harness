# 하네스 수정

하네스 수정은 하네스 구성물의 추가·변경·삭제를 개정안으로 작성해 독립 검수를 거치고, 사용자 승인 후 정본에 반영하는 작업이다. 주 에이전트가 직접 수행하고, 질문과 반환 항목을 사용자에게 제시한다.

## 개정안 작성과 검수

1. 요청이나 진단이 정한 목표 상태를 확인한다. 목표 상태가 모호하거나 대안에 따라 사용자가 원하는 결과가 달라져 사용자 결정이 필요하면 개정안을 작성하기 전에 멈춘다. 질문을 제시하고 결정을 받은 뒤 작성한다.
2. `~/.claude/harness-authoring.md`와 `~/.claude/harness-components.md`를 읽고 개정안을 작성·검수한다. 하네스 파일은 수정 즉시 이후 작업에 적용되므로, 승인 전의 개정안은 `python ~/.claude/scripts/worktree.py new <브랜치>`로 연 worktree 브랜치에 커밋하고, 검수와 제시에는 기준 브랜치와의 차이를 쓴다. 검수 지적의 반영은 `fixup!` 커밋으로 대상 커밋에 붙인다. git 저장소 밖의 하네스 파일은 바꾸지 않고 경로와 diff로 제시한다.

## 반환

다음 항목을 제시한다. 사용자가 확정 문안을 지정해 요청했고 검수 뒤에도 문안이 그대로이며 미해결 쟁점이 없으면 그 지정이 승인이다.

- 개정안: 대상 경로, worktree 브랜치와 커밋 또는 diff, 목표 상태(진단에서는 작용하는 원인), 비교한 대안, 예상 효과·부작용, 확인 방법
- 검수: 검수 결과, 재검수 사용 여부, 처리한 지적, 미해결 쟁점. 검수자를 호출하지 못했으면 준비한 검수 입력
- 사용자 질문과 남은 위험

## 승인 후 적용

승인 과정의 변경을 브랜치에 커밋한 뒤 `land <브랜치>`로 기준 브랜치에 병합하고 worktree를 지운다. git 저장소 밖의 파일은 정본에 직접 반영하고, 필요한 생성물·연결도 반영한다. 승인되지 않은 개정안의 브랜치는 `drop --discard <브랜치>`로 지운다. 재검수와 기록은 공통 하네스 작성 규율의 검증·기록 절을 따르고, 적용 결과로 기대한 변화와 남은 문제를 확인해 보고한다.
