# Pull request 검수

## 조사와 판정

1. 저장소 지침, PR의 base·head와 현재 commit, 본문·대화·검사 결과를 확인한다. 판단에 필요한 변경 내용과 직접 의존성을 조사한다.
2. 변경 목적과 유지해야 할 동작·계약을 기준으로 변경 내용과 필요한 의존성을 검토한다. 발견한 문제는 발생 조건·영향·근거와 확인 범위를 명시하고, merge를 막는지 판단한다.
3. 전체 판정을 요청받으면 발견한 문제와 미확인 범위를 종합해 판단 근거를 제시한다. 지적이 없다는 사실과 필요한 검증이 완료됐다는 사실을 구분한다.
4. 조사 후 대상이나 변경 내용이 달라지면 영향을 받는 판단과 초안을 다시 확인한다.
5. 검수 결과를 사용자에게 보고한다. 다른 기여자에게 전달할 검토 의견의 작성이 요청된 경우에는 게시할 문안을 별도로 구성한다.
6. 검수·merge 가능성에 대한 질문은 판정 요청으로 다루고, 게시나 review state 변경은 별도의 실행 요청으로 다룬다.

## 검토 의견

1. 조사에는 판단에 필요한 자료를 사용한다. 외부 문안에는 게시 대상이 접근할 수 있는 근거나 사용자가 공유를 승인한 정보를 사용한다. 내부 맥락에서 얻은 설명을 포함하려면 공개 범위를 확인한다.
2. 결함 지적은 독립적으로 판단·수정할 수 있는 문제 단위로 구성하고, 발생 조건·영향·근거와 기대하는 동작을 설명한다. 질문이나 제안은 확인할 사항이나 선택의 이유가 드러나게 쓴다.
3. 각 코멘트는 검토자의 판단이나 기여자의 대응에 필요한 정보를 담는다. 같은 문제의 반복은 통합하되, 원인이나 필요한 조치가 다르면 구분한다.

## 독립 검증

검토 의견의 오류·공유 범위·게시 영향에 비례해 독립 검증의 필요성을 판단한다. 사용자 요청이나 필요성·범위에 대한 동의가 있을 때 검증자를 호출한다.

검증자에게 최종 초안과 필요한 근거, 게시 대상·공유 범위·승인 항목을 제공한다. 근거의 충실성, 정보 공유의 적절성, 대상·문안·상태의 일치 여부를 읽기 전용으로 검토하게 한다.

반환된 지적을 근거와 목적에 대조해 처리한다. 추가 검증이 필요하면 남은 쟁점과 필요한 결과를 구체화한다.

## 게시와 확인

게시할 PR과 코멘트 위치·문안·review state를 구분해 제시하고, 승인된 항목만 실행한다. 게시 후 실제 위치·내용·상태가 승인본과 일치하는지 확인한다.
