# Pull request 검수

검수 결과와 외부에 게시할 문건을 분리하고, 사용자가 승인한 항목만 게시한다.

## 조사와 판정

1. base와 head, 현재 head commit, 저장소 지침, 공개된 PR 본문·대화·검사 결과를 확인한다. 판단에 필요한 직접 의존성만 추가로 조사한다.
2. 발견 사항은 차단 여부, 관찰한 동작, 영향, 근거와 확인 범위로 정리한다. PR head가 바뀌면 영향받는 판단과 초안을 다시 확인한다.
3. `Approve 가능한가`, `검수해 줘`와 같은 요청은 상태 판정 요청으로 다룬다. 실제 Approve, Request Changes, 코멘트 게시까지 허가한 것으로 확장하지 않는다.

## 외부 초안

1. 내부 보고와 외부 초안을 별도 산출물로 만든다. 코멘트 하나에는 하나의 수정 가능한 원인을 담고, 관찰된 동작, 영향, 기대 결과가 드러나게 쓴다.
2. 공개된 코드와 대화에서 재확인하지 못한 내부 계획·역할·경로·자료는 사용자가 공개할 사실과 문안을 선택하지 않는 한 외부 초안의 근거로 인용하지 않는다. 보안 또는 비공개 사안은 사용자가 공개 채널을 결정할 때까지 내부에 둔다.
3. 판정이나 요청 대응에 실질적으로 필요하지 않은 통상적인 검사 통과, 작업 과정, 중복 지적, 근거 없는 칭찬과 앞으로 할 내부 작업은 외부 초안에서 제외한다.
4. 게시 전에 정확한 PR·파일·라인, 최종 문안, review state를 구분해 사용자에게 제시한다. 인라인 코멘트 승인을 종합 리뷰나 review state 승인으로 간주하지 않는다.

## 독립 검증

Approve·Request Changes·merge 판단, 여러 코멘트나 종합 리뷰, 내부와 공개 정보의 경계, 보안·개인정보·조직 입장, 여러 저장소를 종합한 주장처럼 영향이 큰 외부 문건은 독립 agent 검증의 후보로 판단한다.

- 사용자가 agent 검증을 명시적으로 요청했거나, 필요성과 검수 범위를 제안해 사용자가 동의한 경우에만 agent를 사용한다. 일반적인 검수 요청만으로 동의를 추정하지 않는다.
- validator에는 최종 초안과 판정에 필요한 최소 자료만 주고, 근거 없는 주장·내부 정보 노출·중복·문체·대상 위치·승인 항목 일치 여부만 검사하게 한다. 파일 수정, 게시, 상태 변경 도구를 호출하지 않는 읽기 전용 역할임을 명시한다.
- validator 사용 승인은 게시 승인이 아니다. 지적을 반영한 최종 문안을 사용자가 별도로 승인해야 한다.

## 실행 경계

- 사용자가 정확한 대상과 review state를 승인하고, 외부 문안이 남는 경우 최종 문안까지 승인한 뒤 해당 항목만 게시한다. 내용이나 대상이 실질적으로 바뀌면 다시 승인받는다.
- 검수 요청만으로 기여자의 source branch를 수정하거나 push하지 않는다. 수정 책임과 branch가 별도로 합의된 경우에만 구현한다.
- 게시 후에는 실제 게시 위치·내용·상태가 승인본과 일치하는지만 읽기 전용으로 확인한다.
