# 코드베이스 아키텍처 개선

## 용어
- Deep Module: 거대한 기능을 가지지만 단순한 인터페이스를 소유함.
- Shallow Module: 단순한 기능을 가지는 작은 단위.

## 구조 원칙
- 필요할 때 마다 Shallow Module을 찍어내지 않는다. 강력한 Deep Module로 묶여있어야 하고, 필요하면 몇번 더 Deep module로 계층적으로 묶을 수 있다.
- 핵심은 코드베이스 전체를 기억하려고 하는게 아니라, 핵심적인 Deep Module 목록만으로 원하는 기능을 찾을 수 있어야 한다.
- 이후 해당 Deep Module내에서 또다시 Deep Module을 탐색하거나, 명확하고 간단하게 정의된 인터페이스를 통하여 원하는 기능과 연관관계를 탐색할 수 있어야 한다.

## 리팩토링 원칙
- 리팩토링에서는'최소 수정'을 고려하지 않는다. 최대한의 개선을 목표로 하여 구조적인 헛점을 전부 제거해야 한다.
- 대신 기존 동작을 유지/보장하기 위한 가드레일을 먼저 고안해야 한다. 예를 들어 테스트 코드 등을 먼저 작성한 뒤에 리팩토링 계획을 세워야 하고, 리팩토링 이후 테스트 통과를 확인해야 한다. 결과를 보고 테스트를 수정하지 않는다.
