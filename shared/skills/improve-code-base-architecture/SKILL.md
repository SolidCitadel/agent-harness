# 코드베이스 아키텍처 개선

## 목표 구조

1. 현재 구조에서의 전환 비용과 분리해, 제품의 목적·제약·변경 요구를 충족하는 목표 구조를 설계하고 사용자와 확정한다.
2. 기능과 변경 지점을 찾고 이해하는 데 필요한 탐색·컨텍스트 비용을 줄이도록 책임과 인터페이스의 추상화를 적극 검토한다. 공통화는 실제로 공유하는 책임과 변경 요구를 기준으로 판단한다.

## 전환과 검증

1. 확정한 목표 구조와 현재 구조의 차이에서 전환 범위·순서·검증 방법을 도출한다. 전환 비용으로 목표 구조를 변경해야 하면 근거와 영향을 제시해 다시 합의한다.
2. 변경 전에 보존할 동작·계약과 그 검증 방법을 정하고 기존 상태에서 확인한다. 전환 후 같은 기준으로 검증한다. 테스트를 변경할 때는 보존할 동작·계약을 계속 검증하는지 확인한다.
