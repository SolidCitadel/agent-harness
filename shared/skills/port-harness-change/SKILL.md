# harness 변경 포팅

1. 원 사건, 확인된 원인, 원본 플랫폼의 완료된 변경과 검증 근거를 수집한다. 원본 변경이 완료되지 않았거나 구현 전에 이미 플랫폼 공통 범위임을 확인했다면 해당 플랫폼의 `self-improve`로 돌아가 범위와 소유자를 다시 정한다.
2. 반대 플랫폼에서 같은 실패 경로가 존재하는지 실제 지침과 지원 표면에 대조한다. 같은 사용자 사건을 다시 겪을 때까지 기다리지 말고 대표 시나리오로 재현 가능성을 검사한다.
3. 모델 성향·도구 이름·hook 입출력·discovery 경로에 종속된 부분과 플랫폼 중립 의미를 분리한다.
4. 같은 원인이 없거나 기존 지침이 이미 실패 경로를 차단하면 수정하지 않고 근거를 보고한다.
5. 같은 원인이 존재하면 대상 플랫폼의 하네스 구성물과 소유 문서를 정하고 수정안·검증 대상을 사용자에게 제시해 승인받는다.
6. 승인된 소유 문서에 플랫폼 중립 의미를 대상 플랫폼의 실행 표면으로 옮긴다. Claude Code rule과 Codex `.rules`는 같은 개념이 아니며, Codex 사용자 skill은 공식 user discovery 경로를 따른다.
7. 대상 플랫폼의 `self-improve` 검증 절차로 최종 상태를 검수한다.
