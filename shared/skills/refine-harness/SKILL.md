# 하네스 정제

{{platform:하네스 작성 규율}}를 읽는다.

## 검토 범위

1. 사용자와 검토 묶음과 목적을 정한다. skill·전역 지침·섹션·workflow 등을 출발점으로, 함께 판단해야 하는 책임과 연결을 확인한다. 사용자가 대상을 사용하며 겪은 문제와 기대를 확인한다.
2. 하네스 작성 규율의 `조사와 판단` 절로 도출한 유지할 요구를 그 근거와 함께 제시해 사용자에게 확인받는다.
3. 현재 판단이나 승인한 변경을 성립시키는 데 필요한 직접 의존성을 확인한다. 다른 책임이나 별도의 결정이 필요한 문제는 현재 묶음에 포함할지 후속 검토로 남길지 사용자와 정한다.

## 개별 판단과 구조 검토

각 규범과 구조 대안의 비용은 로드 시점과 분량, 조건과 예외, agent·tool 호출과 검수 회차, 승인·handoff, 정본과 파생물 수로 확인한다.

1. 묶음 안의 각 규범과 적용 범위·정의·참조·사례 문장을 하네스 작성 규율의 `품질 원칙`·`표현과 참조` 절에 대조해 심사한다. 원문의 기능, 유지·변경 후보, 근거와 사례·반례를 제시하고 판단이 연결되는 항목은 함께 대조한다.
2. 효과의 근거는 사용자 경험, 기록된 사건·진단, 실제 사용 기록에서 찾고, 관찰 근거가 없는 판단은 추론으로 표시한다.
3. 결과를 좌우하는 결정을 사용자와 순차적으로 합의한다.
4. 개별 판단을 모아 문서 내부 구조와 관련 구성물 사이의 책임·순서·중복·참조·배치를 재검토한다. heading 위계를 재검토할 때 `structure-documentation`을 읽고 문서 내부 위계 설계를 따른다.
5. 구상한 변경안을 통합해 변경 전후 문안으로 제시하고, 사용자가 유지할 요구와 대조해 검토하게 한다.

## 반영과 완료

정제 중의 개정은 개정안 구상부터 반영까지 이 절차가 맡는다. 승인한 변경을 정본과 필요한 파생물·연결에 반영한다. 공통 하네스 작성 규율에 따라 검수·검증하고 개정 근거를 기록한다. 기록에는 변경이 효과를 내면 이후 실제 사용에서 관찰될 변화를 포함한다.

심사한 각 규범과 문장에 대한 처분과 이유, 유지할 요구의 충족 여부, 필요한 책임과 읽기 연결을 확인한다. 검수·검증 결과와 미확인 범위, 해결하지 않은 문제와 후속 검토 대상을 구분해 보고한다.
