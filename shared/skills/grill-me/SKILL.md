# 작업 구체화

## 조사

1. 현재 제품, 데이터, 대응 기능과 관련 문서를 먼저 확인한다.
2. 도구로 확인할 수 있는 사실은 사용자에게 묻지 않는다.
3. 기존 불변 조건과 변경 가능한 부분을 분리한다.

## 결정 지도

작업에 해당하는 축만 고른다.

- 목표와 제외 범위
- 사용자와 행위 주체
- 권한·소유권·보안 결정
- 최소 사용자 흐름과 조작 횟수
- 구성요소의 역할과 책임
- 데이터 생성·저장·동기화·복구 수명주기
- 실패·취소·재시도 동작
- 완료 기준과 실제 검증 환경

## 상호작용

1. 의존성이 높은 결정을 먼저 찾고 한 번에 1~3개만 질문한다.
2. 선택지의 근거와 영향을 설명하고 권고안을 밝힌다.
3. 방향·권한·완료 기준을 바꾸지 않는 세부사항은 가정을 밝히고 진행한다.
4. 이미 답한 내용은 다시 묻지 않는다. 새 결정이 기존 합의에 영향을 주면 해당 부분만 다시 연다.
5. 진행 중인 설계의 근거·범위·책임에 질문이나 이의가 생기면 영향받는 결정을 다시 연다. 그 결정과 종속 변경은 읽기 전용 조사와 답변·수정 계약 제안만 하며, 승인 전 구현·보정하지 않고 조사 결과를 완료 판정의 근거로 사용하지 않는다.

## 검수 산출물

- UI: 최소 사용자 흐름, 조작 수, 정보 우선순위와 와이어프레임 또는 격리된 HTML 시안
- 시스템: 컴포넌트 책임, 데이터 흐름, 권한, 마이그레이션과 복구
- 문서: 문서 지도, 독자, 단일 책임, 정본과 링크 구조
- 연동: 입력 원천, 변환 규칙, 인증정보 수명주기와 실패 처리

결정을 돕는 저비용 프로토타입은 최종 구현과 분리하고 미리보기임을 명시한다.

## 합의 완료와 인계

확정된 결정, 명시한 가정, 남은 미결정과 완료 기준을 짧게 정리해 승인받는다. 재작업 비용이 큰 미결정이 남아 있으면 인계하지 않는다. 사용자가 설계 계약을 승인했고 구현 세부사항만 남았으면 관련 실행 skill로 넘긴다.
