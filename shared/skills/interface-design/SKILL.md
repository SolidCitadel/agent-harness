# 인터페이스 설계

## 기준 확인

1. 승인된 사용자 흐름, 정보 우선순위와 완료 기준을 확인한다.
2. 기존 제품이면 대응 화면, 디자인 토큰, 공통 컴포넌트와 상호작용 관례를 조사한다.
3. 현재 화면에 실제로 영향을 주는 시각 축을 식별하고 각각을 기존 정본에서 `상속`, 목적·제약과 관찰 근거로 `결정`, 시안에서 확정하지 않을 `보류`로 구분한다. 타이포그래피, 색과 대비, 간격·grid·breakpoint, 컴포넌트 형태와 상태, 아이콘·motion, 데이터 시각화의 scale·축·encoding 가운데 적용되는 축만 다룬다.
4. 실제 시각값이 들어가는 시안이나 제품 구현 전에 각 구체값을 상속한 정본, 관찰 근거에 적용한 판정 기준, 또는 승인된 선택으로 추적할 수 있어야 한다. 방향·범위나 정보 해석을 바꾸는 선택이 열려 있으면 사용자와 합의하고, 근거로 판정 가능한 세부값은 그 근거를 남기고 진행한다. 저해상도 구조 와이어프레임은 그 전에 만들 수 있지만, 보류한 축의 임시값을 승인된 설계나 구현 입력으로 취급하지 않는다.
5. 기능·탐색·라벨·정보를 시각적 이유로 추가하지 않는다. 제품 결정을 새로 내려야 하면 `grill-me`로 돌아간다.

## 시안

1. 핵심 작업의 조작 수와 상태 변화를 먼저 나타낸다.
2. 결정되지 않은 시각 축만 소수의 근거 있는 대안으로 제시한다.
3. 선택에 따라 정보 위계·가독성·해석이 의미 있게 달라지는 변경은 제품 코드와 분리된 와이어프레임이나 HTML 시안으로 만든다.
4. 정보 위계, 밀도와 핵심 동작을 해당 화면의 실제 콘텐츠로 검수받는다.

## 구현과 검증

1. 승인된 시안과 동작 계약을 그대로 구현한다.
2. 반응형 레이아웃, 클릭 동작, 빈 상태, 오류 상태와 접근성을 확인한다.
3. 실제 화면을 시안과 대조하고 차이를 의도·제약·결함으로 분류한다.
4. 승인된 정보 위계·해석이나 시각 기준과 의미 있게 다른 결과는 통합 전에 다시 확인한다.

독특함은 목적이 요구할 때만 사용한다. 기존 제품과의 일관성, 핵심 정보의 가시성, 조작 비용을 우선한다.
