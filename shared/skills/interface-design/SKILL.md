# 인터페이스 설계

## 기준 확인

1. 승인된 사용자 흐름, 정보 우선순위와 완료 기준을 확인한다.
2. 기존 제품이면 대응 화면, 디자인 토큰, 공통 컴포넌트와 상호작용 관례를 조사한다.
3. 기능·탐색·라벨·정보를 시각적 이유로 추가하지 않는다. 제품 결정을 새로 내려야 하면 `grill-me`로 돌아간다.

## 시안

1. 핵심 작업의 조작 수와 상태 변화를 먼저 나타낸다.
2. 결정되지 않은 시각 축만 소수의 근거 있는 대안으로 제시한다.
3. 시각적 판단이 중요한 변경은 제품 코드와 분리된 와이어프레임이나 HTML 시안으로 만든다.
4. 정보 위계, 밀도, 미리보기, 태그와 핵심 동작을 실제 콘텐츠로 검수받는다.

## 구현과 검증

1. 승인된 시안과 동작 계약을 그대로 구현한다.
2. 반응형 레이아웃, 클릭 동작, 빈 상태, 오류 상태와 접근성을 확인한다.
3. 실제 화면을 시안과 대조하고 차이를 의도·제약·결함으로 분류한다.
4. 사용자 검수가 필요한 차이는 통합 전에 다시 확인한다.

독특함은 목적이 요구할 때만 사용한다. 기존 제품과의 일관성, 핵심 정보의 가시성, 조작 비용을 우선한다.
