# 문서 구조화

## 조사

1. 기존 문서, 실제 구현과 독자가 수행할 작업을 확인한다.
2. 중복된 설명, 정본이 불명확한 정보, 고아 문서와 잘못된 진입점을 찾는다.
3. 제품·운영 결정이 미정이면 문서로 대신 결정하지 말고 `grill-me`로 구체화한다.

## 문서 지도

파일을 만들기 전에 각 문서에 다음 계약을 배정하고 구조 변경이면 사용자에게 검수받는다. 사용자가 이미 같은 지도와 처분을 승인했다면 반복해서 묻지 않는다.

- 대상 독자와 독자의 작업
- 단일 책임
- 포함·제외 범위
- 정본으로 소유할 정보
- 진입 링크와 후속 링크
- 어떤 변경에 함께 갱신되는지
- 기존 문서별 유지·이동·분할·병합·폐기 처분

루트 README는 프로젝트 진입과 문서 라우팅을 맡고, 제품별 문서는 해당 제품의 사용·기능·제약을 맡으며, 공통 시스템 문서는 여러 제품이 공유하는 프로토콜과 데이터 규칙을 맡긴다. 실제 구조가 다르면 독자의 작업을 기준으로 책임을 다시 나눈다.

## 작성과 검증

1. 승인된 지도에 따라 생성·분할·이동·작성한다.
2. 각 문서의 실제 내용과 배치가 승인된 단일 책임·포함 범위·정본·처분에 맞는지 먼저 대조한다. 어긋나면 문서 지도로 돌아가며 기계 검증으로 진행하지 않는다.
3. 의미 대조를 통과하면 같은 설명의 정본을 하나만 남기고 다른 문서는 링크한다.
4. 모든 진입점에서 필요한 문서에 도달하는지 확인한다.
5. 마지막으로 중복, 고아 문서, 깨진 링크와 형식 오류를 기계적으로 검사한다. 이 검사는 승인된 문서 지도나 의미 대조를 대신하지 않는다.
