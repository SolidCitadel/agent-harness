# 자기 개선

## 진단

1. 원 사건과 관련 문서·도구의 실제 상태를 대조한다.
2. 결과가 잘못된 마지막 시점이 아니라 최초로 근거 없는 결정을 확정한 시점을 찾는다.
3. 원인이 발견·결정 정당성·생산 게이트·검증 중 어느 실패인지 분류하고 이를 허용한 발동·정보·판정 기준·도구를 추적한다.
4. 같은 원인이 재발할 범위를 현재 작업·경로, 프로젝트, Codex 전역, 플랫폼 공통으로 판정한다. 원인과 동일한 실패 경로가 확인되지 않은 범위로 넓히지 않는다.
5. 판정한 범위에서 변경을 소비할 하네스 구성물과 소유 문서를 정한다.
	- 현재 작업에만 한정된 원인은 하네스를 바꾸지 않고 작업 안에서 교정한다.
	- 경로·프로젝트 범위는 해당 범위에 실제로 로드되는 가장 좁은 프로젝트 소유자를 고른다.
	- Codex 전역 또는 플랫폼 공통 범위는 `~/.codex/harness-authoring.md`·`~/.codex/harness-components.md`·`~/.codex/self-harness-architecture.md`를 읽고 소유자를 정한다.

## 개입

선택한 재발 범위에서 원인을 제거하는 변경과 같은 원인 사례의 처분을 설계한다.

## 변경과 검증

1. 원인·재발 범위·변경 소유자·수정안·검증 대상을 사용자에게 제안하고 승인받는다.
2. 승인된 소유 문서를 편집한다. 처음부터 플랫폼 공통 범위로 판정한 변경은 한 플랫폼을 먼저 고치지 않고 shared 소유자를 직접 편집한다.
3. 공통 하네스 작성 규율에 따라 개정안을 검수하고 지적을 처리한다. 반영 뒤 승인된 범위에서 같은 원인의 실패가 차단되고, 범위 밖의 정당한 사례가 보존되는지 대조한다.
4. Codex 범위로 완료한 변경 뒤 Claude Code에도 같은 실패 경로가 있음을 새로 확인한 경우에만 `port-harness-change`를 사용한다.
