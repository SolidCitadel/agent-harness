# 하네스 수정

하네스 수정은 하네스 구성물의 추가·변경·삭제를 개정안으로 작성해 독립 검수를 거치고, 사용자 승인 후 정본에 반영하는 작업이다. 수행자는 위임받은 하위 agent이거나 직접 수행하는 주 에이전트이며, 위임받은 하위 agent는 위임 절이나 modify-harness·self-diagnose를 다시 사용하지 않고 개정안을 직접 작성한다.

## 위임

주 에이전트가 하위 agent에 맡길 때 따른다.

1. 부모 대화 이력을 상속하는 하위 agent를 생성한다. 하위 agent가 검수자를 직접 호출하려면 `~/.codex/config.toml`의 `[agents] max_depth`가 2 이상이어야 한다. 지시에는 하위 agent의 역할과 따를 계약, 계기가 된 사용자 발화·지점을 적는다.
2. 하위 agent가 결정이 필요한 질문을 반환하면 사용자의 답을, 검수 입력을 반환하면 작성 대화 이력을 전달하지 않은 새 `harness_reviewer`의 검수 보고를 같은 하위 agent에 전달한다.
3. 반환된 개정안은 사용자 승인 전에는 현재 작업의 기준으로 삼지 않는다. 개정안을 사용자에게 제시해 승인받는다.
4. 승인되면 승인된 최종안과 승인 과정의 변경을 같은 하위 agent에 전달한다. 하위 agent가 `승인 후 적용` 절을 따르며, 전달할 수 없으면 주 에이전트가 그 절을 따른다.

## 개정안 작성과 검수

1. 요청이나 진단이 정한 목표 상태를 확인한다. 목표 상태가 모호하거나 대안에 따라 사용자가 원하는 결과가 달라져 사용자 결정이 필요하면 개정안을 작성하기 전에 멈춘다. 하위 agent는 질문을 반환하고, 직접 수행하는 주 에이전트는 사용자에게 묻는다. 결정을 받은 뒤 작성한다.
2. `~/.codex/harness-authoring.md`와 `~/.codex/harness-components.md`를 읽고 개정안을 작성·검수한다. 하네스 파일은 수정 즉시 이후 작업에 적용되므로, 승인 전의 개정안은 파일을 바꾸지 않고 경로와 diff로 제시한다.
3. 하위 agent가 검수자를 직접 호출할 수 없으면 `~/.codex/harness-review.md`의 입력을 준비해 반환한다. 주 에이전트가 검수 보고를 전달하면 지적을 처리해 다시 반환한다.

## 반환

하위 agent는 주 에이전트에게, 직접 수행하는 주 에이전트는 사용자에게 다음 항목을 제시한다. 사용자가 확정 문안을 지정해 요청했고 검수 뒤에도 문안이 그대로이며 미해결 쟁점이 없으면 그 지정이 승인이다.

- 개정안: 대상 경로, diff, 목표 상태(진단에서는 작용하는 원인), 비교한 대안, 예상 효과·부작용, 확인 방법
- 검수: 검수 결과, 재검수 사용 여부, 처리한 지적, 미해결 쟁점. 검수자를 호출하지 못했으면 준비한 검수 입력
- 사용자 질문과 남은 위험

## 승인 후 적용

승인된 최종안과 승인 과정의 변경을 정본과 필요한 생성물·연결에 반영한다. 재검수와 기록은 공통 하네스 작성 규율의 검증·기록 절을 따르고, 적용 결과로 기대한 변화와 남은 문제를 확인해 보고한다.
